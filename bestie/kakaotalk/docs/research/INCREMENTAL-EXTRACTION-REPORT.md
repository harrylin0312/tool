定位、驗證、讀取分開後，同一程序可維持已驗證的配置及唯讀 handle，在短交易之間快速查詢，無須為每個查詢複製或掃描整份資料庫。跨重啟的安全配置仍屬設計。SQLite 即使以唯讀模式開啟 WAL，也涉及 SHM、檔案鎖及關閉時機。直接讀 App 路徑先保留為待驗選項，隔離副本是本輪確認可用的模式。正式共用連線前，另核對所選 SQLite／SQLCipher 版本的 WAL 修補。本次內嵌版本落在 SQLite 文件列出的舊版範圍，實驗沒有驗證其是否帶有回補；官方所述 WAL-reset 問題涉及同時寫入或 checkpoint 的連線，未在本輪測重現。[SQLite WAL](https://www.sqlite.org/wal.html#read_only_databases) · [SQLite WAL-reset 修補說明](https://www.sqlite.org/wal.html#the_wal_reset_bug) · [SQLCipher 相容設定](https://www.zetetic.net/sqlcipher/sqlcipher-api/#pragma-cipher_compatibility)

## 游標、索引與生命週期

- 3,126 筆按 logId 排序後有 0 個重複 ID、0 組相鄰 sentAt 逆序，167 組時間秒值包含多筆。這是單一歷史快照的順序，沒有觀察寫入先後，無法證明之後補載都會落在游標後方。
- 全量及游標查詢使用 NTChatMessage 的 (chatId, logId, msgId) 主鍵索引，游標計畫包含 chatId 等值與 logId 範圍。以 128 筆分頁共 25 頁，ID 與單次全量順序完全一致，漏列及重複皆為 0。按 sentAt 排序的重疊查詢只用房間前綴，並產生暫存排序。另發現 (chatId, threadId, logId) 前綴索引、討論串 (chatId, threadId) 及作者 (userId, linkId) 索引。
- 合成 SQLCipher 在高水位不變時更新舊列及插入比高水位小的 ID。只查高水位後方漏 2 筆，完整對帳漏 0 筆，無變更重跑產生 0 筆變動。合成作者改名及 Thread 記錄可獨立讀出。原生快照有 16 筆 revision 非零，仍無實際狀態轉移樣本可證明 revision 涵蓋所有變更。
- scope 2 在 R3 截止前 308 筆都未以同秒同名出現在主聊天 CSV。歷史 App 討論串面板的一串 40 筆中，39 筆是 scope 2、1 筆是 scope 3；當時的 App 主聊天畫面也有該 scope 3 成員。scope 1 無 threadId 的觀察與「主聊天室」假設一致。這些是特定範圍的支持證據，未驗證 bitmask，也未覆蓋撤回和隱藏後的可見性。保留原碼和房間／串關聯，未知情況交給後續介面驗證。[歷史面板與 CSV 證據](NATIVE-DATA-AUDIT.md)
- 實機未人為觸發訊息撤回、刪除、管理員隱藏、引用變更與暱稱變更。type、status、scope、revision、引用與 Threads 欄位都保留。舊列消失先標記「來源暫未觀察到」，待完整一致性重讀與事件語義核對。

## 監聽、故障與合成測試

| 方案 | 觀察 | 選擇 |
| --- | --- | --- |
| 固定間隔輪詢 | 200 ms 合成週期中，在刻意不接收檔案通知的案例，提交後約 140 ms 被查到。延遲取決於觸發相位、查詢成本及睡眠狀態。 | 作保底，也用於定期對帳。 |
| 只監聽檔案 | macOS kqueue 立即等待的 20 次提交都收到通知，提交返回到取出已排隊／即時通知的中位 0.001 ms。5 次未逐次消費的提交只得到 1 次通知。以新檔取代舊檔後，舊描述符漏掉對新檔的寫入，目錄通知及重新註冊可恢復。 | 適合作提示。上述微秒數是通知取出時間，不是從新訊息送出到顯示的延遲。 |
| 監聽加輪詢 | 合成測試各自證實通知取得、重綁及輪詢補抓。完整長期排程和整合延遲仍待實測。 | 推薦。先監聽目錄、主檔及 WAL，用 debounce 合併通知，保留低頻輪詢與喚醒重查。 |

同一合成 SQLCipher writer 提交後，既有唯讀交易仍讀舊快照，交易結束後看得到新資料；同一 handle 的 data_version 隨外部提交而變。持有舊讀取交易時，writer 的 TRUNCATE checkpoint 回傳 busy；讀取交易釋放後成功。合成 writer／reader 關閉後 WAL 消失，重啟後重建，資料庫替換後重新連線通過。模擬本機入庫交易中斷時，訊息、游標及事件全數回滾；重新連線重播兩筆後漏送與重複事件皆為 0。上述結果只適用受控樣本，尚未在實際 App 持續寫入中持有直接唯讀連線，也未測真實 App 關閉、重啟、checkpoint、休眠喚醒或帳號換庫。data_version 只比較同一連線的先後值。[SQLite data_version](https://www.sqlite.org/pragma.html#pragma_data_version)
