## 獨立 Threads 與畫面

第二份快照有 3,125 筆訊息資料及 **189 筆 NTChatThread**。189 個 threadId 均對應同房間一則無 threadId 的根訊息。189 個 lastLogId 均對應同串訊息。訊息表共 837 筆非零 threadId、218 個不同 threadId，其中 189 個有討論串表紀錄，29 個只有訊息表證據。837 筆分布於 scope 2（363 筆）及 scope 3（474 筆）。討論串表的 count 與實際可查到的成員數在 173／189 串相同，其餘 16 串須保留兩個計數。不得把 count 當作資料完整性保證。

以曾從 KakaoTalk 討論串面板直接取得的輔助使用介面文字做獨立抽查，避開既有 OCR 和 HTML 配對。一個顯示 40 則回覆的討論串，以根正文唯一定位後，原生 40 則成員與畫面 40 則正文的多重集合完全一致。其中 39 則 scope 2、1 則 scope 3。兩次連接即時 KakaoTalk 視窗皆逾時，本輪沒有補齊 R2 五組引用的即時逐筆畫面驗收。舊面板抽樣只支持這一串成員關係，不能替代其他串及引用的畫面驗證。

## 主資料庫試建與遷移建議

1. 建立平行的本機資料庫，將原生訊息、引用、Thread 成員、事件原始代碼各自保存。保留來源、採樣時間、時間精度及方法。依房間與原生 ID 唯一定位，保留引用在當時的預覽，停用舊的文字猜測自動覆蓋原生關係。
2. 把正式 CSV、舊 HTML 和既有翻譯當作獨立來源。只有證據唯一的映射才移轉翻譯及書籤 ID，保存原 HTML ID 的對照。遇到同文、編輯、暱稱差異、分鐘對秒或時間缺失，標記待核對。保留舊來源才有的歷史紀錄，連同來源標籤及原時間精度。兩份資料有衝突時保留證據供複核。
3. 在隔離副本做增量、重啟、重跑、舊訊息修改／撤回、Threads 及書籤恢復試驗。補做指定 App 畫面抽樣及 HTML 唯一對照以外的差異分類。通過後再評估切換主要來源；本次不重建或替換正式資料庫，不更新快照或網站。
