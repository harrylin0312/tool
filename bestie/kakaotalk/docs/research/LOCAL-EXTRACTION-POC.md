## 存取需求與風險

擁有者已授權隔離建置 SQLCipher 與在本機使用此帳號的解鎖材料。已檢查偏好設定的直接 ID 欄位，以及既有清單中 4 個數字候選。將候選依公開程式碼與本機裝置資訊核對預期資料庫檔名，精確匹配為 0。程式因此在複製及開啟正式資料庫前停止。尚缺可驗證的帳號數字 ID 或同一檔案的有效解鎖材料。該材料可解鎖整個帳號的本機資料庫，權限範圍比本次查詢的單一房間大。應由本機程序在記憶體內使用，不透過命令列參數、日誌、遠端服務或 Git 傳遞。優先使用現有檔案讀取權限。若系統權限仍阻礙，先報告確切檔案及錯誤，不預先授予完整磁碟存取。此次沒有還原雜湊、暴力枚舉識別碼、開啟正式資料庫或更改系統權限。數字候選失配無法區分是帳號識別來源不符，抑或新版資料庫檔名規則改變。

## 真實資料驗收

1. 先驗證唯讀 SQLCipher 可開啟候選格式與現有 WAL。使用同一唯讀交易取得跨表快照。有副作用疑慮時改用 App 結束後取得的穩定主檔與附屬檔副本，保留主檔和 WAL 的配對。核對原始資料庫檔案未因實驗而改動。
2. 以指定標題與 Open Chat 屬性確認恰好一個房間。後續的訊息、作者與引用查詢必須限定該房間或其 Open Chat linkId。重名或找不到便停止。
3. 選取 20～50 則與正式 CSV／快照重疊的訊息，至少 5 組引用以 KakaoTalk 畫面及快照另行確認。記錄逐欄對應、時間差、缺漏、重複、錯連與預覽截斷。原生 ID 以十進位字串輸出，附件 ID 使用保留數值精度的解碼方式。只提交彙總數與驗收結果。


## 2026-11-28｜獲授權後的實機結果

- **資料庫定位成功。** 授權後在本機以四個程序枚舉帳號雜湊，第一次實測 45.9 秒找到匹配，重跑為 44.8 秒。依該帳號識別與裝置資料核對檔名，只有一個檔案匹配。SQLCipher 4.12.0 使用相容模式 3 成功唯讀查詢；模式 4 只在合成資料驗證。
- **WAL 副本與唯讀查詢。** 複製主檔和現有 WAL 前後，比對來源雜湊及副本雜湊，檢查期間相符。在私人暫存目錄使用副本，SHM 由副本讀取環境管理。用唯讀模式、query_only 和同一交易查詢。這是單次穩定副本驗證，持續寫入與重啟的測試留待 R4。
- **指定 Open Chat。** 查詢要求標題吻合、為 Open Chat，且恰有一個房間才返回資料。限定該房間的 chatId 和 linkId 查訊息與作者。台灣時間 11/25 22:30:20 至 22:34:58 共 50 則，訊息 ID 全部唯一，50 則均取得作者 ID 和房間暱稱。64 位元 ID 以 SQL 字串取出，訊息 ID 經 BigInt 往返 50/50 一致。引用 ID 以文字比對，再對照原生訊息 ID。
- **CSV 與快照比對。** 日期轉為台灣時間後，正文、暱稱與秒級時間三欄在正式 CSV 唯一且完全吻合 43/50。另有 47/50 可唯一配對時間與暱稱，差異仍待逐筆分類。原文快照按作者及正規化正文唯一配對 41/50。原生資料含 8 組回覆目標，其中 6 組兩端都能與快照的已確認連結比較，6 組目標相同，0 組錯連，6 組引用正文是目標正文的前綴或全文。其餘 2 組尚無足夠對照。
- **畫面與未測範圍。** 僅使用先前本機保存的 KakaoTalk 畫面辨識資料，獨立核對到 2 組回覆；未重新逐筆觀看 5 組即時畫面。未驗證獨立 Threads、各類系統事件、刪除語義、全量涵蓋率或持續增量擷取。6 組快照核對可支持後續 R3，畫面部分仍需補驗。

實機小樣本驗證了原生 ID、作者及引用鏈路。後續應先釐清未對應的記錄，再擴大 R3 及執行 R4。正式頁、發布器、原始資料庫及聊天室皆未變更。樣本和解鎖資訊留在本機。
