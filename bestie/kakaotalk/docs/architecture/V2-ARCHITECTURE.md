# KakaoTalk Reader V2 架構

基準 `1071dd72474564cab85bc32b5f49cd49ceb24f5a`。P2 開發分支為 `dev/kakaotalk-native-v2`。

## 三層服務

| 服務 | 職責 |
| --- | --- |
| Mac 即時伺服器 | Mac 可運作且連線時持續擷取、保存，將事件交給客戶端。翻譯是獨立工作，原文入庫後立即可讀。 |
| GitHub Pages | Mac 無法提供服務時，客戶端可用最近一次有效的加密快照。閱讀器和資料分離，資料分塊加密，版本 Manifest 指出資料世代、事件序號、區塊版本及完整性資訊。 |
| 客戶端離線快取 | 無網路時讀取上次成功保存的快照和事件。快取核對身份、完整性和事件次序後，才以原子方式切換版本。 |

三層共享物件 ID、資料世代和事件序號。相同世代的 GitHub 快照水位低於快取時，持續使用快取。不同世代的序號無法直接比較，客戶端須經可信的世代轉換與完整快照驗證，才切換命名空間。若 GitHub 快照失敗、區塊缺件或 MAC 驗證失敗，繼續使用最近一次有效資料。安全更新與快取儲存是後續交付。

快照初始政策為有變更時每 30 分鐘發布，累積 100 則新訊息可提前發布。一般自動發布至少間隔 15 分鐘。正常停止時嘗試發布尚未同步資料，保留手動立即發布，無資料變更即略過。停止前與手動的明確操作可跳過一般自動間隔。時間、門檻與是否啟用皆由未來發布器設定管理。

## P2 共用核心

`native-v2/core` 以 Python 標準函式庫搭配已核准的 SQLCipher 執行。初次定位的輸出是私人本機路徑、房間及解鎖材料。日常 CLI 使用已知路徑取得封存一致副本，核對其世代及房間，再透過預備的唯讀 SQLCipher 查詢介面轉成統一模型。實作不需 MCP 或翻譯模型。直接開啟 App 路徑前須另行驗證並行 WAL 安全性。同步引擎只依賴 source.open() 及 reader 契約，日後可以替換資料源。

索引游標處理新列，近期重疊處理尾端變動，週期性對帳補低 ID 或較舊異動。作者及 Threads 的小型索引每輪核對。取得讀取上界後同一快照分頁；完成核對才在同一筆旁路交易持久化物件、事件與游標。P2 的單輪使用穩定副本，交易長度不影響 App 寫入。將來直接連線須改用經驗收的短交易。

P2 提供一致性資料及事件序列。後續檔案監聽、定期同步、翻譯、快照發布與 SSE 各自排程，讀同一套本機契約。P2 沒有常駐或遠端服務。

## P2.1 信任邊界及資料世代

在已有旁路資料的環境，正常同步由單一已綁定的本機擷取流程簽發收據。綁定記錄 canonical path、檔案身分、來源世代及序號，收據覆蓋封存內容與來源資訊。只接受該綁定的最新簽章收據；收據過期或來源換檔會安全停止。這是本機擷取順序，KakaoTalk 未提供更強的原生內容版本證明。如果相同 inode 被外部工具原地倒回，新的本機收據無法保證 App 資料較新。應避免繫結外部副本或以外部工具修改 App 資料。

外部 seal 沒有可信收據，可作空庫初次歷史基準，或經兩項明確復原選項在新來源世代完整對帳。舊來源資料透過本機證據及人工審核投影進入歷史，和原生同步無關。來源世代與本機服務世代分離，即使同房間換來源仍可保留本機歷史；旁路備份還原會強制輪換本機事件世代。

獨立見證檔應放在一般 SQLite 備份集合之外的持久私人位置。作業系統同帳號可存取的檔案層並非硬體信任根；全部媒體同步回退時仍須外部可信單調狀態。P3 及 P5 應以固定水位的物化批次作消費契約，維持原有三層快取不倒退規則，等待第二輪獨立 QA 後再開工。[一致性協定](EVENT-PROTOCOL.md)
