# V2 本機資料模型

一個旁路 SQLite 對應一個唯一匹配的 Open Chat。Schema 有私有格式標記及 PRAGMA user_version，逐版移轉由本機交易保護。版本 1 建表，2 加索引，3 加獨立舊證據及來源身分，4 拆分翻譯輸入版本、加入可顯示歷史、來源收據及事件鏈。P2 舊庫首次遷移使用 adopt，保留原物件與證據，建立外部見證並旋轉世代。

| 表 | 意義 |
| --- | --- |
| objects | 訊息、作者和 Threads 的最新正規化狀態。物件 ID 由房間、類型、原生 ID 確定性產出。version 涵蓋全部內容及狀態。input_version 獨立反映實際翻譯輸入。P2.1 的輸入僅為原文正文。 |
| sources | 每個物件目前採用的原生觀察、來源世代及原始欄位。原始附件留在本機。 |
| replies | 回覆物件 ID、目標原生 ID、引用時的預覽及解析證據。目前目標正文另外讀取。 |
| thread_members | 原生 threadId 與訊息的關係。暫無串中繼紀錄時仍保留成員。 |
| translations | 以訊息、語系及原文輸入版本為鍵，欄位 original_version 沿用舊名稱。提交時檢查 input_version，投影只輸出目前輸入版本的有效譯文。 |
| legacy_records | App 匯出、畫面衍生、HTML 或未知來源的本機原始證據。 |
| legacy_views、legacy_assertions | 經獨立審核的可顯示歷史與舊書籤映射。保留來源類別、不可逆來源代號、時間精度、可信度及映射狀態。 |
| sync_state、metadata | 本機資料庫家族識別、事件世代、來源世代、來源檔案身分、最近收據、封存時間、高水位和最後對帳。 |
| events | 維持追加式順序，與物件投影、關係和同步游標同時提交。 |

舊版譯文以舊物件版本為鍵。遷移時以當時物件版本開出初始 input_version，舊譯文原樣保存，僅當舊版已與所在物件的當前版本對應，才在投影保持有效。若舊版本內容無可核對的原文證據，保留本機紀錄供人工判斷。之後僅在正文改變時遞增 input_version；status、scope、引用及作者顯示名保持獨立。

原生 ID 以 SQLite 整數查詢、十進位字串輸出。type、status、scope、revision、subType、contentFlag 保存原值。查不到的行保留為 not_observed，不以此判定撤回。

legacy_records 的保存不影響公開水位。經審核且已保留原始證據的顯示欄位才可顯示。按正文、作者及可重疊時間抑制相同或疑似重複的顯示項；有映射或映射歧義的歷史行和重複別名也保留於本機。已發布的歷史內容新增、修改或被原生資料抑制，均會進位事件。模糊或文本被改寫的跨來源同一性仍需人工照查。
