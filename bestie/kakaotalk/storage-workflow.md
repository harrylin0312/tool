## 後續每次照這個順序

1. **開工記基準。** 核對正式副本、遠端 main 與線上快照版本。記起始游標、上次固定版截止時間，以及私人主資料夾和本次工作區容量。單檔可用 `stat -f %z 檔名` 量 B，資料夾用 `du -sk 目錄` 量磁碟配置 KiB；同一輪前後使用同一口徑。
2. **增量工作、可斷點接續。** 文字匯出以重疊訊息接續。回覆掃描分批進行，只有唯一對得上的原訊息才建連結。未通過已知樣本驗證前保留為候選。現有原型尚未把掃描游標及候選合併入庫，重跑會覆寫候選 JSON；先保存待審結果，切勿把未掃區段當作已完成。
3. **發布前確認使用的版本。** 上次資料夾裡同時有 544,593 B 的帶游標版和 600,825 B 的日期索引版。後續應從當前線上版本與資料庫產生候選，核對日期／時間索引、更新游標和舊書籤。11/26 的一次性腳本內有固定日期、編號或分支；換批次需要先核對。若本機 main 領先，僅發布本次授權的內容，完成後整合正式本機副本。
4. **驗證後再輪替。** 建議保留最近成功匯出、一份可還原的上一版，以及尚待審核的來源。先驗證資料庫能還原、明文可重建日期索引和既有引用、線上新密文能解開，再列出可清理的翻譯中間檔、測試頁、停用的測試環境及其容量。歷史 Git 物件會繼續佔空間：截至 `63c1588` 的 12 個不同 HTML blob 合計 3.25 MB，本機 Git 回報這些物件的儲存量約 2.51 MB。每次全量重新加密仍會新增歷史物件，偶爾集中發布可減少成長。
5. **每輪只留一列本機用量紀錄。** 例：`日期｜來源列數／新列數｜新增檔 B｜工作區前後配置 KiB｜下載次數／本文 B｜成功掃描頁／像素｜截圖落盤 B｜候選結果 B｜實刪檔數／刪前 B｜發布 SHA／阻礙`。下載可用 `curl --compressed -o /dev/null -w '%{http_code} %{size_download}' 公開頁面網址` 記錄，勿帶專用網址金鑰。刪除前量單檔，成功後累計；缺少歷史計數器的欄位寫「未量」，不要從資料夾淨變動推算。平常不必為了一列用量紀錄部署 Pages。
