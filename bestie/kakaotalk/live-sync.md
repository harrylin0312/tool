# KakaoTalk 韓中對照｜即時同步設計

目前 GitHub Pages 提供加密快照。本文記錄 Mac 即時擷取、iPhone 遠端閱讀和快照發布的共識與驗收方法。即時模式仍待實作與實機驗證。

## 資料存放與讀取

| 位置 | 用途 | 寫入時機 |
| --- | --- | --- |
| Mac 的 `~/Library/Application Support/KakaoTalkReader/chat.sqlite3` | 主資料庫，保存原文、繁中翻譯、回覆關係、同步游標與擷取狀態 | 每批擷取完成即寫入。翻譯或引用後續辨認完成時更新原記錄 |
| Mac 上的私人閱讀網頁 | 沿用現有聊天版型，由同一服務提供網頁、歷史查詢和即時事件 | 讀取 SQLite，透過 SSE 傳送新增與更新 |
| GitHub Pages | 可在 Mac 離線時閱讀的加密快照 | 預設手動按「發布快照」。可選擇「結束擷取時自動發布」，且只在資料有變更時發布 |
| NAS（選用） | 可供還原的加密資料庫備份 | 用 SQLite 備份機制取得一致副本，再加密並備份 |

網頁用事件序號接續更新。Mac 讀取新訊息後先存原文並推送，繁中翻譯完成後再推送同一筆的更新。訊息與對應的更新事件在同一個資料庫交易內寫入，避免資料已寫入而重連後看不到這次更新。Safari 回到前景時重新確認游標，從最後收到的事件補齊。歷史與即時事件使用同一個 HTTPS 來源。

## Mac 擷取方法

1. **限定聊天室。** 即時擷取可在 Mac 上開關。啟用時只讀取使用者指定、已登入的 KakaoTalk 聊天室。休眠、登出或找不到指定視窗時，更新擷取狀態並保留既有資料。
2. **正文優先走 macOS 輔助使用介面。** 讀取暱稱、正文、顯示時間和列順序。先實測 KakaoTalk 是否提供可靠的變更通知，並用定時檢查補漏。比對相鄰多則訊息的順序與內容來定位重疊區間。避免只用「暱稱＋時間＋正文」當唯一鍵，因為同一人可能在同一分鐘真的連發兩則一樣的訊息。
3. **回覆另外擷取。** Threads 面板可讀的原訊息和串內回覆用輔助使用介面處理。主聊天室引用則測試用 ScreenCaptureKit 取得指定視窗，再用 Apple Vision OCR 讀取「Reply to」與引用片段。以暱稱和原文匹配先前訊息，只有唯一可確認的對象才建立連結。仍有歧義時，保存引用片段和「待確認」狀態。KakaoTalk 顯示原訊息無法載入時，保留該狀態。引用的繁中翻譯取自原訊息。
4. **補抓後才更新擷取游標。** Mac 重新上線時，由最新訊息回查到上次已保存的多筆重疊區間，依聊天順序寫入漏掉的訊息。若 KakaoTalk 已載不到銜接點，記下可能缺漏的時段，網頁顯示「可能缺漏」及最後成功擷取時間。

## 私人連線與 GitHub 發布

- Mac 網頁服務只綁定 `127.0.0.1`，由 Tailscale Serve 提供私人 HTTPS。用 tailnet 政策限制能存取該服務的裝置，並驗證從 iPhone 行動網路可讀、離開 tailnet 後無法連上。
- GitHub 只接收加密後的快照與讀取頁程式。每次快照使用新的 AES‑GCM nonce。金鑰、原始聊天、SQLite、截圖、OCR 暫存與擷取日誌留在授權的本機或備份位置。文件、範例及 commit 訊息也不放專用解鎖網址。
- 發布時記錄快照涵蓋到哪個事件序號。GitHub Pages 成功上線後才顯示「已發布」。若失敗，保留本機資料和上一個已發布的版本，重試仍以同一份候選快照為準。

## 已驗證與待驗收

先前在 Mac 上由工具操作 KakaoTalk，逐頁擷取歷史正文，留下 446 筆快照紀錄。回覆則透過 Threads 面板或畫面引用框核對，再由程式配對。最新快照有 71 組可雙向跳轉的回覆，以及 1 則原訊息無法載入的回覆狀態。這份快照可用來驗證匯入、翻譯及跳轉回歸。

即時模式先在 Mac 本機驗收，再開放遠端讀取。測試時以 KakaoTalk 畫面為基準，記錄漏抓、重複、配錯和延遲。

- **快速來訊。** 連續訊息與同一分鐘的重複正文都要按原順序留下。若來訊超過一頁，回查應能補齊。
- **引用。** 驗證一般引用、畫面截短、同暱稱同文、討論串及原文無法載入。待確認的候選不得產生錯誤跳轉。
- **Mac 狀態。** 分別測前景、背景、最小化、鎖屏、睡眠喚醒與 KakaoTalk 重開。正文與 OCR 的結果分別記錄。若需要保持視窗可讀，網頁應顯示擷取暫停。
- **iPhone 重連。** 測試行動網路、切換 Wi‑Fi、離開 Safari 再回到前景。資料接續時應保留原本的閱讀位置，且沒有重複訊息。
- **快照發布。** 驗證未啟用自動發布時只在手動操作後發布，以及部署失敗後能安全重試。
