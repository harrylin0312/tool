# KakaoTalk 原文發布工具第二輪獨立驗收

驗收日期 2026-11-28（台灣時間）。候選 commit 為 `c1bf0c86227f02bcf8405685be01fdb9819af989`，測試分支為 `test/kakaotalk-cross-batch-replies`。

**建議合併 main。** 第一輪的 QA-01、QA-02、QA-03 均以原故障條件重測通過。本輪已測功能未發現回歸。首次遷移仍須由操作者從獨立確認的原始 CSV 取得可信基準。

## 環境與資料

- Linux x86_64、Node.js v24.22.3、npm 11.19.1、Python 3.12.14、npm 正式套件 `linkedom` 0.18.15。兩支候選版原有回歸測試各自執行並通過。
- 使用與第一輪逐位元組一致的正式 CSV（2,457 列）和加密原文快照。確認候選版的原文與 CSV 交接密文 Git blob 與第一輪一致。以隔離副本執行發布器並用原金鑰解密實際產出，核對資料和 DOM。
- 用候選版 `node live/history-digest.mjs <可信原始CSV> 2457` 計算舊原文遷移基準。同一份可信原始 CSV 另取 1,380 列前綴，以同一工具計算舊翻譯初始化的基準。兩者分別經環境變數 `TRUSTED_HISTORY_SHA256` 傳入。故意改動的 CSV 只作為候選輸入。
- 以 Headless Chromium 158.0.8127.0 在本機開啟實際加密頁，使用專案原有的路徑形式與原金鑰，驗證 390×844 觸控視窗和 1440×900 桌面視窗。

## 第一輪故障複驗

| 案例 | 重現條件與預期 | 第二輪實測 |
| --- | --- | --- |
| QA-01 舊翻譯快照覆蓋新原文 | 原文已更新到 2,465 列。保留舊翻譯快照，用正式 CSV 的前 1,381 和 1,380 列執行 `node live/publish-original.mjs current.csv previous.csv`，並提供舊前綴的可信基準。預期拒絕覆寫。 | **通過。** 報錯「原文快照已存在，禁止重新初始化」。密文逐位元組一致，重新解密仍為 2,465 列。另在原文輸出不存在的隔離副本測試相同兩份 CSV，缺少基準不產出檔案，有正確基準則可建立並解密為 1,381 列、1,383 個訊息或事件 ID、71 組引用。 |
| QA-02 首次遷移接受被修改的歷史 | 用尚無歷史雜湊的正式原文，修改 CSV 副本中一筆原來可唯一映射的歷史正文，保持欄位、列數、作者和時間，其餘相同。預期拒絕修改副本，隨後仍接受正確來源。 | **通過。** 缺少基準或使用可信原始 CSV 的正確基準時，修改副本均被拒絕，舊輸出逐位元組一致。正確 CSV 在缺少或格式無效的基準時也被拒絕。有正確基準時遷移成功，解密確認存入預期前綴雜湊。移除環境變數後用正確 CSV 重跑，密文逐位元組一致。 |
| QA-03 新建引用折疊原文換行 | 在正式 CSV 副本加一則兩行短訊息及一則引用它的回覆，透過審核檔指定關係。預期引文還原原正文及換行。 | **通過。** 解密後引文有兩個 `<br>`，分別位於作者後及正文兩行之間。連同原文符號逐字核對一致。Chromium 兩種寬度均實際渲染出正文兩行，桌面也有明確的分行，CSS 內容相同。 |

## 回歸驗證

| 項目 | 實測結果 |
| --- | --- |
| 正式回歸腳本 | `node live/test-publish-original.mjs` 和 `node live/test-publish-integration.mjs` 均通過，另以正式 CSV 和真實 `linkedom` 獨立解密比對。 |
| 歷史資料與來源映射 | 既有 2,459 個 ID 與順序一致，核對 2,027 則一般訊息與 432 個有 ID 的事件。1,890 個唯一映射逐筆核對無誤，包含 1,608 個 CSV 列號與 HTML ID 數字不同的映射。正文、暱稱、顯示時間、事件節點、舊頭像顏色和原有回覆均保留。快照截止正確接到 CSV 末筆完整時間。 |
| 跨批次、同批次與歧義 | 第一次遷移保留 214 組雙向回覆及 107 個不可跳轉引用。正式 CSV 副本第二批加 7 列，第三批再加 1 列。檢查新訊息回覆正式歷史、同批次訊息及前一批訊息。指定正文與列號可從同秒、同作者、同文的兩筆中選定正確目標。最終逐邊核對 218 個正向與 218 個反向連結，錯向、缺漏及重複 ID 皆為 0。歧義、逆序、引用無時間事件及既有引用衝突均被拒絕。 |
| 冪等與故障保護 | 正式 CSV 遷移後重跑、帶審核資料的第二批重跑均保持密文逐位元組一致。舊 CSV、已鎖定歷史正文變更、錯誤金鑰、錯誤配對均被拒絕。另以唯讀目的目錄使暫存寫入回傳 `EACCES`，現有密文逐位元組一致。 |
| DOM、CSS 和排版 | 95 個既有特殊頭像和舊頭像顏色保留，新訊息沿用相同作者的一般背景色或特殊頭像。新無時間事件無補造日期，仍是置中事件。回覆清單仍在訊息內容欄。手機及桌面抽樣同一則舊原文像素一致，既有氣泡、字體和頭像尺寸一致，整頁無橫向溢出。 |
| 導覽與 AES-GCM | 兩種視窗都實際測了依日期或日期加時間跳轉、引用來回跳轉、跳至最新、標記進度及更新後恢復書籤。目錄尾斜線和 `index.html` 路徑共用進度，頁內跳轉保留 fragment。各次成功更新的 nonce 不同，原金鑰可解密。缺少或錯誤金鑰時頁面保持鎖定。 |

## 驗收範圍

- 137 個既有一般訊息仍缺少可唯一確認的 CSV 來源映射。已比對其原文、ID 與保留順序。
- 實際瀏覽器測試限 Chromium，未測 iPhone 或 macOS Safari 實機。並行發布、程序強制終止及遠端部署故障亦未納入本輪。
